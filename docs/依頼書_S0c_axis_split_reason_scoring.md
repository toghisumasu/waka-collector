# 依頼書 S-0c：軸別呼び出し × 結論先出し・理由後置による qwen3:8b スコアリング（S-0b との直接比較）

> フェーズ番号「S-0c」は仮称。Nobuson の口頭指示（2026-09-30）を文書化したもの。

## 1. 目的

S-0b（軸別・数字のみ）では、`material_gap` と `scene_gap` が3にほぼ完全に固着した（それぞれ 296/297、297/297）。Nobuson の指摘は次の2点。

- 説明を出させた方が安定する
- 結論を先に出させ、説明は後ろに置く方が扱いやすい。禁止表現（「説明は不要」など）は 8b には避けた方がよい

本依頼では、S-0b から **プロンプトの指示文だけ** を変え、固着が変わるかを見る。判定・閾値決定・本番配線は行わない。

## 2. S-0b からの差分（これ以外は同一）

| 項目 | S-0b | S-0c |
|---|---|---|
| 指示文 | `JSONのみを出力せよ。説明は不要。` | `最初の行に次の形式のJSONで結論を出力し、次の行から評価の理由を1〜2文で述べよ。` |
| num_predict | 60 | 300（理由を書き切らせるための必然の変更） |
| パース | 最初の `{...}` | 最初の `{...}`（同一。結論が先頭のため） |

同一に保つもの: `/api/generate`、`stream:false`、`think:false`（API パラメータ）、temperature 0.3、repeat_penalty・seed・`format` は送らない、単発の独立呼び出し、前句・付句の本文のみ、尺度の文言、parse 失敗は1回だけ再試行、99ペア × 3軸 × 3試行 = 891 呼び出し、順序は試行 → ペア → 軸。

### プロンプト（season_gap の例。material_gap・scene_gap は定義行とキーだけ替える）

```
あなたは連歌の付合を評価する。次の前句と付句を読み、「季節感の離れ」を1〜5の整数で評価せよ。
1 = ほぼ同じ・非常に近い、5 = まったく異なる・非常に遠い。

最初の行に次の形式のJSONで結論を出力し、次の行から評価の理由を1〜2文で述べよ。
{"season_gap": n}

前句：{maeku}
付句：{tsukeku}
```

## 3. 実施内容

- `script/score_minase_pairs_qwen8b_split_reason.rb`（S-0b のスクリプトを複製して新規作成。S-0・S-0b 側は変更しない）
- 試走: pair 1・32・50・71 × 3軸 × 3試行 = 36 呼び出し。停止基準は S-0b と同じ（最終 parse 失敗が 4/36 以上、または `n` のオウム返しが1件でもあれば全走せず報告して停止）
- 全走: 891 呼び出し。`nohup` で実行し、ログを `tmp/` に残す
- 出力: `tmp/minase_qwen8b_split_reason_raw.csv`（呼び出し単位。理由の文は `raw_output` 列に残る）、`tmp/minase_qwen8b_split_reason_summary.csv`（ペア単位。S-0 と S-0b の中央値列を併記）
- 記述統計は S-0・S-0b・S-0c の3版を並べる（度数分布、3軸の組の種類数、unstable、bui 距離との Spearman、pair 1・71、季移りの層別、parse 失敗と再試行）。**解釈・閾値の提案はしない**
