## 交絡要因(切り分け不能)

**Ollama 更新の影響と、コード変更の影響は、この実験では切り分けできない。** 9/19 以降に以下が変わっており、いずれも遅延と品質に影響しうる。

- OverlapGuard(614226e, 9/27): :direct の前句エコーを抑制する。エコー検出時に再生成が走る設計なら、1 句あたりの試行回数が増え、遅延の主因になりうる。今回の中央値が 14→54 秒に動いた点と整合する(要検証)。
- num_predict / repeat_penalty(bc97363, 9/29): 出力長の上限は遅延を縮める方向。repeat_penalty は生成内容を変え、リトライ率に影響しうる。
- temperature の options 内移動(863f7d0, 11/2): 「既定挙動は不変」とコミットされているが、それ以前に temperature がトップレベルで無視されていた場合、実効 temperature が変わり、生成内容とリトライ率に影響した可能性がある(要確認)。
- 辞書・部立更新(10/3〜10/12、風体の新設、一座一句物 21 語等): 式目違反の判定が増え、リトライが増える可能性。052 の植物去嫌 FORCED もこの系統。
- observe スクリプト(OBSERVE_RG_TIMEOUT 600 秒、プロンプトログ書き込み)や F-3/F-4 のログ形式変更。
- 実走時の負荷: 実走中の他プロセスは未監視(開始時 load average 1.5 程度。本検証中の他ジョブ有無は未記録)。
- モデル本体は同一(qwen3:14b, ID bdbd181c33f2, 5 か月前のもの)で、モデル更新は交絡ではない。
- 9月の 3 run 自体が 97〜137 分とばらついており、ベースラインの揺れが大きい。

## 所見

- 速度は **悪化**(総時間 +48〜108%、中央値約 4 倍)。ただし原因が Ollama 0.40.15 かコード変更かは判定できない。eval rate 11.4 tok/s という単発値だけでは、更新前との比較基準がない。
- 更新を維持してよいか: 現時点のデータでは「更新が悪い」とも「無関係」とも言えないため、この結果だけで維持/撤回を決めるべきでない(依頼書で Ollama のダウングレードは対象外)。
- 切り分けの提案(いずれも別依頼・承認要):
  1. 最小の A/B: 同一 Ollama で、コードを 9/19 時点(c9d7b09 前後)に戻した worktree で数十句走らせ、中央値が 14 秒に戻るかを見る。戻れば原因はコード側。戻らなければ Ollama 側。
  2. 句ごとの生成試行回数・Ollama 応答時間をログに出す計測の追加(OverlapGuard のリトライ数の把握)。
  3. 同一プロンプトでの `ollama run --verbose` 比較は、旧バージョンが残っていないため不可。
