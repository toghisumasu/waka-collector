## 依頼書の判断基準に照らして（本番 `:direct` = renga_verses n=111 で判定）

| 判断基準 | 該当 |
|---|---|
| 3割合がほぼ均等（各33%前後）→ **生成品質に構造的な問題あり** | **付句 33.3 / 36.9 / 29.7 → 該当** |
| ピタリが過半数 → 現状維持 | 非該当（33%） |
| 字余り／字足らずに偏り → 原因分析 | 字余り微優勢だが差は小（37 vs 30）、明確な片寄りではない |

### 所見

1. **本番インタラクティブ（`:direct`）はピタリ 1/3 で、依頼書の「構造的問題あり」に該当。** 平野連歌会で実際に出るのはこの経路。
2. 誤り方向は **字余りやや優勢だが両方向に散っている**（37% / 30%）。片方向だけの対策では半分しか拾えない。
   - ※ 当初版で「字足らずに絞る」と書いたのは `:waka_extraction`（mcflag）の数値を本番と取り違えたため。撤回する。
3. `:waka_extraction` は mora 精度で明確に上（ピタリ 46〜81%）。ただし4ステップで遅く、Step3 の31音収束・deflock（`docs/phase0_deflock_report.md`）等の未解決課題あり。

### 推奨する次アクション（要人間判断）

いずれかを改善依頼書として起票:

- **案A: `:direct` の mora 収束を直接改善。** 5×5ループの許容判定（`(mora - target).abs > 1` で reject）は既に ±1 を許しており、ピタリ狙いなら「±1 を feedback で詰める」段を追加する等。字余り・字足らず両方向を対象にする。

## 追記 2026-09-08: `:direct` の誤差分解と案2実装

`sono39_*`（`:direct`・本番同条件）の付句 diff 分布 n=2089:

```
 -1音: 571 (27.3%)
 ±0音: 669 (32.0%)   ← ピタリ
 +1音: 820 (39.3%)
 ±2以上:  29 ( 1.4%)
```

- **誤差の 66.6% が ±1、±2以上は 1.4% のみ。** 生成品質は良く、5×5ループの採否判定
  `(mora - target).abs > 1` が ±1 をそのまま採用して最後の1音を詰めないのが低ピタリ率の主因。
- 方向スキュー（句種別）:
  - 長句（目標17）: −1が42% / +1が23% → **字足らず寄り**
  - 短句（目標14）: +1が55% / −1が13% → **字余り寄り**
  - モデルは目標に依らず 15〜16 音へ回帰する。

### 対策案（効果順）

1. **案1: ±1リペア段**。採用直前が ±1 のとき「あと1音だけ調整」で1〜2回再詠、ダメなら ±1 句へフォールバック。±2以上が 1.4% なので ±1 の半分を拾えればピタリ 32%→50%超。コスト: Ollama 呼び出し +1〜2回/句。
2. **案2: プロンプトの目標音数をドリフトの逆へバイアス**（レイテンシ増ゼロ）。長句「18音でよい、やや長めに」/ 短句「13音でよい、やや短めに」。→ **2026-09-08 実装済み（commit 9597e82、`renga_generator.rb:461`）**。採否判定は 17/14 ±1 のまま。
3. 案3: 前半試行のみ「ピタリのみ採用」に締める（既存リトライ予算を活用、案2と併用）。
4. 案4: 機械的±1補正（`ENDING_BY_MORA` を実適用）。句が硬くなるため案1失敗時のフォールバック止まり。

### 案2 の次アクション

100句規模の観測バッチ（`:direct`）を走らせ、**長句の字足らず率（現42%）・短句の字余り率（現55%）の低下**を確認する。効果が出れば案1を追加検討、出なければ案1へ切替。
