## 0. 前提の確認：このログで「step1」「step3」は観測できるか

先に結論から述べる。**今回のログでは調査項目0〜3に実データで答えることができない。** 理由は以下の通り。

1. 対象ログは`:direct`戦略（`RengaGenerator#generate_tsugeku`）の実行結果で、`script/observe_production_hyakuin.rb`が記録するのは「外側のMAX_RETRYループ（1〜5回）の各試行結果」のみである。
2. `generate_tsugeku`内部にはさらに5×5=25回のLLM呼び出しループがあり（`app/services/renga_generator.rb:157-252`）、この内部ループの個々の生成結果（＝ユーザーが想定する「step1自由詠み」「step3モーラ詠み直し」に相当する呼び出し）は**どこにも記録されていない**。ログに残るのは、内部ループが最終的に採用した1句（成功時）か、25回すべて不採用に終わった場合の空文字列（`生成失敗`）のいずれかのみ。
3. 生LLM出力（`first_line`で1行抽出する前のraw）を保存している箇所はコード全体を検索しても存在しない。`Rails.logger.info`で記録されているのは処理時間（秒数）のみで（`renga_generator.rb:119,190,254`）、生成テキストの内容は一切ログに出力されない。
4. さらに、「step1（自由詠み）」「step3（モーラ詠み直し）」というラベル自体が`:waka_extraction`戦略専用（`StepwiseWakaGenerator`のcallsログ/stepwise_stepsログ）のものであり、今回検証対象の`:direct`戦略には存在しない区分である。この点は直前のコミット846501dのコミットメッセージ自体が「`step3_mora_rewrite`という名称は`stepwise_waka_generator.rb`（`:waka_extraction`戦略専用）のログラベルであり`:direct`戦略には存在しない」と明記している。

したがって、「step3のモーラ詠み直し出力でモーラ不足時に説明文が短いか」という比較は、**モーラ詠み直し（socratic_mora_messagesまたはmora_feedback_message経由の再試行）で生成された個々の候補テキストがそもそもログに残っていない**ため、この10句サンプルでは検証不可能である。
