# 調査報告書：`season_from_text` MeCabベース置換 Phase 0調査

- 依頼書：`docs/依頼書_season_from_text_mecab_phase0.md`
- 参照コミット：`44bbaf4`（Phase1 run100集計クローズ時点）
- 本調査はすべて読み取り専用。`app/`・`dict/user_entries.csv` は無改修。
  検証に使ったスクリプトはRuby/rails runnerでMeCab解析を再現しただけで、Ollama呼び出しは一切行っていない。

## 結論の先出し

- 単純部分一致由来の**誤検出**（文法カテゴリの取り違え）は理論上・MeCab解析上は複数語で実証できたが、
  **実際にログ上で発火した実害ケースは「しも」1件のみ**（Phase1 run100、実害なし）。他の候補語
  （さむ・きり・あやめ 等）が誤検出を起こす具体的な非季語文脈は、過去の全観測ログ（47ファイル・
  create/retry 3698件）を検索しても一度も出現していない。
- 一方、`forced_zatsu`の主因として既に特定済みの**「露」の偶発混入**（[[sono85_must_continue_phase1]]・
  本報告書§3）は、「露」がMeCab上も正しく`名詞`として解析される**真の**季語であり、
  問題は品詞ではなく「その語を選んだ意図」という意味論の領域にある。**MeCab品詞判定では解決できない**。
- したがって、MeCab置換は「しも」型バグを体系的に予防する効果はあるが、経路1の主要因（露の偶発混入）
  には無効。**投資対効果は限定的**。推奨は §5-6 案αの**限定適用**（次フェーズは低優先度）。
- 副次的な発見として、`bui_dictionary.yml`の`season:`タグと`SEASON_WORDS`が**同じ語で矛盾**している
  ケース（蓬／よもぎ＝夏 vs 春）を1件確認した（§4-3）。これは季判定ロジックとは独立した既存データの
  不整合であり、MeCab移行の可否とは別に是正候補として記録する。

## 1. `season_from_text`の現行実装・呼び出しマップ

### 1-1. 実装は3箇所に独立して存在する

同じ「テキスト中に季語が部分一致するか」というロジックが、**用途ごとに個別実装**されている
（共通化されていない）。

| 実装 | 場所 | 用途 |
|---|---|---|
| `RengasController#season_from_text` | `app/controllers/rengas_controller.rb:210-214` | 履歴（history）・生成句候補（candidate）の`[:season]`確定 |
| `RengaGenerator#compute_season_tag(upper, lower)` | `app/services/renga_generator.rb:338-341` | seed pool 構築時、Wakaの上句+下句から`seed[:season]`を確定 |
| `RengaGenerator#maeku_season` | `app/services/renga_generator.rb:416-418` | `filter_pool`のフォールバック分岐（季ヒント無指定時、前句自体から季を推定） |
| `StepwiseWakaGenerator#maeku_season` | `app/services/stepwise_waka_generator.rb:363-365` | 上記の`:waka_extraction`版（`season_label_for`のフォールバック） |

いずれも`RengaGenerator::SEASON_WORDS.find { |_, words| words.any? { |w| text.include?(w) } }`という
**同一の部分一致ロジック**を個別に書いている。加えて`script/verify_seed_completion.rb`・
`script/verify_pool_expansion.rb`にも`SEASON_WORDS`定数と同ロジックが**丸ごとコピー**されている
（app/との二重管理）。修正時はこの重複箇所すべてに反映する必要がある。

### 1-2. 呼び出しマップ（結果の影響範囲）

`RengasController#season_from_text`の戻り値は`history`・`candidate`の`[:season]`に入り、以下2系統に分岐する：

```
season_from_text(text)
  └→ history[:season] / candidate[:season]
        ├─ ShikimokuChecker#kukazo_violations（app/services/shikimoku_checker.rb:144-187）
        │    └→ 実際のNG判定（句数:季節）。current_season_streak（同ファイル250-254行）が
        │       history[:season]の連続数を数え、上限超過(kukazo_over)・転換時最短未達(kukazo_under)を判定。
        │       ★ここでの誤検出は「本来ok/ngが逆転する」実害に直結する。
        └─ ShikimokuChecker#compute_season_hint（同507-518行）
             └→ next_constraints[:season_hint]（current/count/must_continue/must_switch）
                  ├─ StepwiseWakaGenerator: sample_seed（案C）・shift_window_to_kigo（案F）・
                  │    directive_lines（案A）の入力（stepwise_waka_generator.rb）
                  └─ RengaGenerator: filter_pool・season_label（:direct方式、renga_generator.rb）
```

`compute_season_tag`（seed pool の`season`タグ）は`sample_seed`／`filter_pool`の季別抽選母集団を決め、
`maeku_season`は季ヒント未指定時のフォールバック判定に使われる。**いずれも最終的に
`kukazo_violations`のNG判定・`compute_season_hint`の生成誘導へ合流する**ため、誤検出の影響範囲は
「実際のNG判定」と「生成時のプロンプト誘導」の両方に及ぶ（Phase0/Phase1で確認した「幻の季セグメント」
は後者の経路）。

## 2. SEASON_WORDSの全語彙と品詞混同リスク一覧

`SEASON_WORDS`（`app/services/renga_generator.rb:39-44`）全62語を、MeCab単体解析
（`RengasController#build_mecab`と同一のユーザー辞書込みインスタンス）に通した結果と、
非季語コンテキスト文でのトークン化実験（§2-2）に基づき分類した。

### 2-1. リスク階層

| 階層 | 定義 | 該当語 |
|---|---|---|
| **Tier1（実害確認済み）** | 過去ログで実際に誤検出が発火 | しも（1件、実害なし） |
| **Tier2（品詞混同・実証済み、実害ログなし）** | MeCab解析で「季語と異なる品詞」に解釈される非季語文脈を作成でき、かつ本文中でも同様の混同が理論上起こり得る | さむ・きり・あやめ |
| **Tier2'（MeCab標準辞書で複数トークンに分割＝真陽性ですら単純比較依存）** | 季語自身がMeCab標準辞書で1トークンとして認識されない | よもぎ・ききょう・もみち・みぞれ・かれの・ふきのとう |
| **Tier3（漢字1字・複合語埋没リスクは理論上あるが実害ログなし）** | 漢字1字が非季語の複合語に埋没する可能性（`include?`は拾うがMeCabトークン単位では拾わない） | 露・月・鹿・枯・霜・嵐 |
| **Tier4（低リスク）** | 3字以上の複合ひらがな語・固有性の高い語で、非季語文脈での偶発一致が想定しにくい | 上記以外の45語（かすみ・うぐいす・わらび・たんぽぽ・すみれ・ほととぎす・五月雨・卯の花・青葉・さみだれ・竜田・おみなえし・千鳥 等） |

### 2-2. Tier1・Tier2の実測結果（MeCab解析）

| 語 | 季 | 単体解析 | 非季語文脈での実験 | 判定 |
|---|---|---|---|---|
| しも | 冬 | `しも[助詞,副助詞]` | 「光りしも手のひらに静けさ」→`しも[助詞,副助詞]`。既知バグの再現。 | **誤検出**（品詞=助詞、MeCab POSチェックで排除可能） |
| さむ | 冬 | `さむ[形容詞,自立]` | 「うらさむしき夜更けかな」→`さむし[形容詞,自立]`の一部。「さむらいが刀を抜く」→`さむ[形容詞,自立]`+`らい[名詞,一般]`（標準辞書が「侍」を認識せず誤分割）。 | 季語としての単体解析は形容詞語幹。**名詞限定チェックで排除可能**（ただし「さむ」は元々`SEASON_WORDS`上も名詞として登録されておらず、この語自体が品詞的に季語らしくない設計） |
| きり | 秋 | `きり[名詞,一般]` | 「思いきり走り出す」→`思いきり[副詞,一般]`という1トークンに融合。「区切り」「仕切り」はいずれも漢字表記のため`include?`ヒットなし。 | 副詞化する文脈は**トークン境界（形態素単位で完全一致するか）で排除可能** |
| あやめ | 夏 | `あやめ[名詞,一般]` | 「あやめも分かぬ闇の中」（文目＝分別、の意）→`あやめ[名詞,一般]`。菖蒲と全く同じ品詞・同じ表層形で出力される。 | **MeCabでは解決不可能な同形同品詞異義語**（標準辞書は意味を区別しない） |

### 2-3. Tier2'の実測結果（季語自身が標準辞書で複数トークンに分割される）

| 語 | 季 | MeCab単体解析 |
|---|---|---|
| よもぎ | 春 | `よ[助詞,終助詞]` + `もぎ[動詞,自立]`（「蓬」が1語として認識されない） |
| ききょう | 秋 | `き[動詞,自立]` + `きょう[名詞,副詞可能]` |
| もみち | 秋 | `も[助詞,係助詞]` + `みち[名詞,一般]` |
| みぞれ | 冬 | `みぞ[名詞,一般]` + `れ[助動詞,*]` |
| かれの | 冬 | `かれ[動詞,自立]` + `の[助詞,連体化]` |
| ふきのとう | 春 | `ふき[名詞,一般]` + `の[助詞,連体化]` + `とう[副詞,助詞類接続]` |

これらは**現行の`text.include?`方式なら正しく検出できる**が、もしMeCabトークン単位の完全一致
（サーフェス一致）へ置き換えると、ユーザー辞書に追加登録しない限り**検出漏れ（偽陰性）が新たに発生する**。
`dict/user_entries.csv`（9件）にはこの6語のいずれも未登録（§4-4）。

### 2-4. Tier3の実測結果（漢字1字が複合語に埋没する例）

| 語 | 季 | 埋没する非季語複合語の例 | MeCabトークン化 | `include?`判定 |
|---|---|---|---|---|
| 露 | 秋 | 吐露・披露宴 | `吐露[名詞,サ変接続]`／`披露宴[名詞,一般]`（露は独立トークンにならない） | ヒット（誤検出候補） |
| 月 | 秋 | 毎月・先月 | `毎月[名詞,副詞可能]`／`先月[名詞,副詞可能]` | ヒット（誤検出候補） |
| 鹿 | 秋 | 馬鹿げた・鹿児島 | `馬鹿げ[動詞,自立]`／`鹿児島[名詞,固有名詞]` | ヒット（誤検出候補） |
| 枯 | 冬 | （気力が）枯れ果てし | `枯れ[動詞,自立]`（1字の「枯」ではなく「枯れ」という語幹+送り仮名トークン） | ヒット（誤検出候補、ただし意味上は「枯れる」の比喩的用法で季節との関連は文脈次第） |
| 霜 | 冬 | 霜降り（肉） | `霜降り[名詞,一般]`（1トークンに融合） | ヒット（誤検出候補） |
| 嵐 | 秋 | 嵐山 | `嵐山[名詞,一般]`（1トークンに融合） | ヒット（誤検出候補） |

いずれのケースも**MeCabのトークン境界と`SEASON_WORDS`の1字が一致しない**ため、
「形態素として独立した1文字トークンが季語と一致する場合のみ検出」という設計にすれば理論上排除できる。
ただし「枯」のように**季語自体が動詞語幹（送り仮名込みで基本形が変化する）**場合は、単純な表層一致では
真陽性（枯野・枯れ木など）も一緒に失うため、語幹（見出し語／lemma）ベースの判定が必要になる
（§4-2で後述）。

## 3. ログから確認できた実害ケースの集計

- 検索対象：`log/observation_sono*.jsonl`（47ファイル、`create`/`retry`レコード合計3698件）＋
  Phase1 run100専用の`log/stepwise_steps_20260902.jsonl`（2100レコード）。
- **Tier1「しも」**：Phase1 run100のv15→v16のみ1件。前回報告（[[sono85_phase1_run100]]）どおり
  実害なし（v16の実出力「遠きかすみに霜の粉降る手のひら」は結果的に本物の霜語彙も含んでいた）。
- **Tier2・Tier3の非季語複合語**（さむらい・馬鹿・披露・吐露・毎月・先月・今月・来月・鹿児島・嵐山・
  霜降り・思いきり・あやめも・文目）：全47ファイルを検索し、**出現ゼロ**。仕切り・区切りは検出されたが
  いずれも自己ログのメッセージ文字列（`"区切り不一致"`という診断issue名がステップログに残っているだけ）
  であり、生成句本文には一度も出現していない。
- 露の偶発混入（Tier外・意味論的リスク）：Phase1 run100だけで季セグメント開始16件中7件（前回報告
  §7-2）。全ログ横断の集計は本調査のスコープ外だが、単一run100でもこの規模で発生しており、
  母数（3698 create/retry）に対する希少性という点でTier1〜3とは性質が異なる**支配的な要因**である。

**結論**：Tier1〜3の「品詞混同・トークン埋没」系の誤検出は理論上実証できるが、実運用での発生頻度は
極めて低い（全履歴でしも1件のみ）。露の偶発混入は品詞混同ではなく語彙選択の問題であり、
発生頻度・実害規模ともに現状最大の課題だが、本調査の対象（MeCab品詞判定）では解決しない。

## 4. 既存MeCab基盤との連携可能性

### 4-1. `VerseTextAnalysis#morphemes_of`はそのまま使える

`app/services/verse_text_analysis.rb:23-33`の`morphemes_of(text, nm)`は、形態素ごとに
`{surface:, yomi:, mora:, feature:}`を返す。`feature`は生のMeCab feature CSV文字列
（`品詞,品詞細分類1,...`）なので、`feature.split(",")[0] == "名詞"`のようなチェックを追加するだけで
POSフィルタが実装できる。**新規の解析基盤は不要**、既存の`morphemes_of`を呼び出し側
（`RengasController`・`RengaGenerator`・`StepwiseWakaGenerator`いずれも`include VerseTextAnalysis`
していないが、`RengasController`は独自に`nm.parse`を呼んでいるので同じ書き方に合わせれば済む）。

### 4-2. lemma（基本形）が必要なケースがある

`morphemes_of`が返す`feature`には基本形（活用語の見出し語）も含まれる
（IPADic準拠、featureのインデックス6が基本形）。「枯」のような動詞語幹型の季語は、
表層一致ではなく基本形一致（`枯れる`）でチェックする必要がある。IPADic標準の`feature`列で対応可能
（`WakaUnidicAnalyzer`のような別辞書は不要）。

### 4-3. `BuiDictionary`のseason タグは流用できない（矛盾あり）

`app/data/bui_dictionary.yml`（45エントリ）のうち`season:`が設定されているのは14語のみ
（紅葉・梅・桜・花・柳・荻・薄・萩・蓬・時雨・東風・月・いとゆふ・帰雁）。`SEASON_WORDS`（62語）とは
語彙のカバレッジが大きく異なり、**「露」「かすみ」等、経路1の主犯語は`bui_dictionary.yml`に
登録すらされていない**。

さらに、**同じ語で季判定が矛盾している既存バグを1件発見した**：

| 語 | `SEASON_WORDS`（renga_generator.rb） | `bui_dictionary.yml` |
|---|---|---|
| 蓬／よもぎ | `spring`（春） | `season: 夏`（夏） |

`bui_dictionary.yml`のコメント（同ファイル該当行）を確認する限り、この`season:`フィールドは
句去ルール（`kukazo_rules`の季連続判定）向けではなく、別の用途（植物細分化と紐づいた表示・分類目的）で
入力された可能性があり、`SEASON_WORDS`と同期を取る運用にはなっていない。**案γ
（BuiDictionaryの季語タグを活用してSEASON_WORDSを廃止・統合）を採る場合、この矛盾をどちらかへ
統一する作業がまず必要**になる。

### 4-4. ユーザー辞書（`dict/user_entries.csv`）とのギャップ

9エントリ中、`SEASON_WORDS`と重複するのは**紅葉・東風・時雨・五月雨**の4語のみ（読み補正目的）。
§2-3で確認した「MeCab標準辞書で複数トークンに分割される」6語（よもぎ・ききょう・もみち・みぞれ・
かれの・ふきのとう）は**いずれも未登録**。トークン単位でのMeCabベース判定へ移行する場合、
其の六十五（かりね・かりふし）と同じ手順でこの6語をユーザー辞書へ追加登録する必要があり、
実装コストに直接反映される。

## 5. 設計案の比較

| 案 | 内容 | 実装コスト | 効果 | 副作用・リスク |
|---|---|---|---|---|
| **α：ひらがな語彙のみPOSチェック追加** | `SEASON_WORDS`のひらがな語（しも・さむ・きり等）にのみ、MeCabトークンが対象語と表層一致し、かつPOSが「名詞」であることを追加要求。漢字表記は現行の部分一致を維持。 | 小（`season_from_text`系メソッド3箇所への数行の条件追加＋Tier2'6語のユーザー辞書登録） | Tier1（しも）・Tier2（さむ・きり）の品詞混同を体系的に排除。Tier3（漢字埋没）は対象外のため無効。 | Tier2'6語をユーザー辞書登録しないと偽陰性が発生する（要対応）。あやめ型の同形同義語は解決しない。 |
| **β：SEASON_WORDS全体をMeCabベース判定に置換** | 漢字1字語も含め、全語をトークン完全一致＋POSチェック（一部lemma一致）に統一。 | 中〜大（62語すべての品詞・活用パターンを個別検証、Tier3の「枯」等はlemma判定の追加実装、3箇所の重複実装＋script/2ファイルの整理が前提） | Tier1〜3すべてを理論上解消。ただし実害ログでの検証対象がTier1の1件のみのため、効果測定が困難。 | 実装・回帰テストのコストが大きい割に、実害ゼロだったTier3のために既存の`kukazo_violations`（実NG判定）の挙動が変わるリスクがある（保守的に動いていた部分一致が急に検出漏れを起こす可能性）。露の偶発混入には無効なので、期待するforced_zatsu改善効果は得られない。 |
| **γ：BuiDictionaryへ統合し`SEASON_WORDS`を廃止** | 季語タグを`bui_dictionary.yml`の`season:`フィールドに一本化し、`SEASON_WORDS`と3箇所の重複実装を廃止する。 | 大（§4-3の矛盾解消＋48語の新規season登録＋3箇所の呼び出し元とscript/2ファイルの改修＋`kukazo_rules`との整合確認） | データの二重管理を解消し、将来の語彙追加・修正が1箇所で完結するようになる（保守性向上）。品詞混同そのものは解決しない（別途αの仕組みと併用が必要）。 | 最も影響範囲が広く、`kukazo_violations`（実NG判定）に直結するデータを丸ごと移し替えるため、回帰リスクが最大。今回のスコープ（品詞混同リスクの是正）に対しては過剰。 |

## 6. 推奨案と次フェーズの実装方針

- **短期的には「変更しない」が正当な選択肢**：実害ログはしも1件・実害なしのみであり、Tier2・Tier2'・
  Tier3はいずれも理論上のリスクに留まる。緊急対応が必要な状況ではない。
- 対応するなら**案αの限定適用**を推奨する：
  1. `しも`・`さむ`・`きり`・`あやめ`（Tier1・2）のみ、対象語がMeCabトークンとして独立し
     `品詞=名詞`であることを追加条件にする（`あやめ`は同形異義語のため効果なし、実装上は含めても害はない）。
  2. Tier2'の6語（よもぎ・ききょう・もみち・みぞれ・かれの・ふきのとう）をユーザー辞書へ追加登録し、
     トークン化の前提を整える。
  3. Tier3（露・月・鹿・枯・霜・嵐）は今回のスコープ外とする：実害ログがゼロであり、
     「枯」のような動詞語幹型はlemma判定の追加実装が必要で費用対効果が低い。
  4. `bui_dictionary.yml`の`蓬`（夏）と`SEASON_WORDS`の`よもぎ`（春）の矛盾（§4-3）は、
     MeCab移行とは独立に**別途是正が必要**（正しい季の確認から人間判断を仰ぐ）。
- **経路1（幻の季セグメント、露の偶発混入）への対応は別軸**：本調査で確認した通りMeCab品詞判定は

- 次フェーズで実装に進む場合は、本調査の案α限定版を対象に、3箇所の重複実装（`RengasController`・

## 7. 案α実装結果（「しも」誤検出修正）

- 依頼書：`docs/依頼書_season_from_text_shimo_fix.md`
- 実装：`app/controllers/rengas_controller.rb`の1ファイルのみ（`season_from_text`にPOSチェック分岐＋
  `shimo_kigo?`ヘルパー追加、内部3呼び出し箇所へ`nm:`引き渡しを追加）。`RengaGenerator`・
  `StepwiseWakaGenerator`・他のSEASON_WORDS語彙は無改修（§6の推奨どおり「しも」のみに限定）。
- D-33-1に従い実装前にdiffを人間へ提示し、承認を得たうえで実装した。

### 7-1. MeCab事前検証結果（依頼書§4-1）

「しも」を含む文13パターン（依頼書指定2文＋既知バグ再現＋追加の古典的用例・名詞用例）を
`RengasController#build_mecab`と同一のMeCabインスタンスで解析した。

- **IPA辞書は「しも」を単体では一度も`名詞`と判定しなかった**（13文すべてで`助詞,副助詞`）。
  「しもの降る朝」「庭にしも置きて」「しも白く置く葉の上」のように文脈上は霜（名詞）を意図した
  文でも同様で、辞書に「しも」の名詞エントリ自体が存在しないと判断できる。
- 一方、漢字「霜」は文脈によらず常に`名詞,一般`と正しく解析される（「霜の降る朝」「庭に霜置きて」
  いずれも確認）。
- **依頼書の想定と異なる点を1つ発見**：依頼書は「しもやけ・しもつきは1形態素として解析されるため
  対象外」としていたが、実際は`しも[助詞]+やけ[名詞]`のように**分割される**（「しもふり」も同様）。
  この想定は誤りだったが、今回の実装方式（「しも」トークン単体のPOS判定）はこれらの複合語にも
  正しく機能するため実装上の問題にはならなかった。

### 7-2. 実装方針の最終形（フォールバックは不採用）

事前検証13例中「MeCabが名詞と判定したケース」が0件だったため、**依頼書§2 step5のフォールバック
（隣接形態素からの推定）は不採用とした**。既存の全パターンで「助詞と判定されたら除外」だけで
正しく動作しており、根拠のない分岐を追加すると検証できないコードが増えるだけと判断したため
（実装前にこの逸脱を含めて人間承認を得た）。

最終ロジック：`season_from_text(text, nm: nil)`の中で、「しも」の照合だけ`shimo_kigo?(text, nm)`へ
委譲し、MeCabで対象トークンが明示的に`名詞`と判定された場合のみ季語として扱う。`nm:`はキーワード引数
＋デフォルト`nil`のため、外部スクリプト（`script/observe_waka_extraction.rb`等）や
`spec/controllers/rengas_controller_spec.rb`の既存の1引数呼び出しは無改修で動作する
（該当ブランチに入った場合のみ内部で`build_mecab`を新規に呼ぶ）。
