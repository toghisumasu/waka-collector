# 作業依頼書：UniDic和歌版の並行運用に向けた基盤実装（rev.2、対象リポジトリ・稼働環境訂正版）

- 起票日：2026-07-26
- 対象リポジトリ：waka-collector
- 前提フェーズ：Phase 0（調査、`docs/phase0_unidic_koshabun_report.md`）完了

---

## 1. 概要

Phase 0（調査）の検証結果を踏まえ、既存のIPA辞書ベースのモーラ判定ロジック（`ku_validator.rb`）を**完全維持**しつつ、古典連歌の解釈・恋語彙検出等の高度な分析（ローカルLLM連携等）用途として、**「UniDic和歌版」を別インスタンスで並行運用**するためのサービス構造を構築する。

## 2. 背景と目的

- **背景**：UniDic和歌版の導入により恋語彙検出率等の向上（理論上53.8%へ回復）が見込まれる一方、現代国語の感覚（人間の読み手）に基づくモーラ判定との乖離、および素性列構造の相違が発生する。
- **目的**：本番のバリデーション基盤を既存IPA辞書のまま保護しつつ、宗祇時代の連歌の趣・文脈を解釈するAI向けの解析層として、別インスタンスのUniDicを安全に並行稼働させる。

## 3. 設計方針（並行運用）

1. **既存コードの完全保護**：`app/` 配下の既存バリデータ（`ku_validator.rb` 等）には一切手を加えない。差分0行を維持する。
2. **新規サービスクラスの作成**：UniDic和歌版専用の `Natto::MeCab` インスタンス生成および素性パースを行う専用サービス（`WakaUnidicAnalyzer`）を新規作成する。
3. **インデックス管理の分離**：UniDic和歌版の素性列構造は新規サービス側のみで吸収・処理し、外部へは正規化済みの構造体で返す。
4. **ユーザー辞書の併用考慮**：過剰分割（「行方」等）を防止するため、ユーザー辞書（`-u`）を読み込めるインターフェースを設ける。
5. **辞書非同梱・環境変数外出し**：辞書本体はリポジトリに含めず、環境変数で参照する。未設定時はサービスを無効化し、既存機能に一切影響を出さない（graceful degradation）。

## 4. 作業内容・スコープ

### ① 辞書ファイルの配置整理

- UniDic和歌版（ver.2025.12 等）の配置パス決定と展開。**リポジトリ外、または`tmp/`配下（既存`.gitignore`の`/tmp/*`規則でカバー済み）**へ配置する。
- 参照は環境変数 `WAKA_UNIDIC_DICDIR`（辞書ディレクトリ）、`WAKA_UNIDIC_USERDIC`（ユーザー辞書 `.dic`、任意）で行う。
- ライセンス条件（CC BY-NC-SA 4.0）の確認。**非営利限定**であるため辞書本体および派生物はリポジトリに同梱しない。
- `.gitignore` に以下を追加：
  - `dict/`配下に置く場合を想定した予防的除外パターン（`dict/unidic-waka*`、`dict/unidic_user_entries.csv`、`dict/unidic_user.dic`）
  - ※ユーザー辞書のコンパイル成果物にもSA（継承）条項が及ぶ可能性があるため、配布物には含めない方針とする。
- `docs/reference/`に、辞書入手元・展開手順・ライセンス条項を記載する。

### ② 新規サービス／ラッパーの実装

配置：`app/services/waka_unidic_analyzer.rb`

- **インスタンス管理**：UniDicは辞書が重いため、リクエスト毎に `Natto::MeCab.new` しない。クラスレベルでシングルトンとして保持する。
- **素性列の扱い**（重要 / 当初依頼書からの修正点）：
  - `features[6]` は **語彙素読み（lForm）** であり、表層の読みではない。活用語では終止形の読みを返すため「けり／ける」の区別が消える。
  - したがって、以下を併せて取得し正規化して返すこと。

    | 用途 | 素性 | 索引 |
    |---|---|---|
    | 語彙素読み | lForm | `features[6]` |
    | 語彙素 | lemma | `features[7]` |
    | 発音形 | pron | `features[9]` |
    | 発音形基本形 | pronBase | `features[11]` |

  - 恋語彙検出等で表層一致を見る場合は `pron` 側を用いる。`lForm` のみに依存しない実装とする。
- **列数の防御**（重要 / 当初依頼書からの追加点）：
  - 和歌版のビルドによって素性列数が異なる場合がある。
  - 索引をハードコードせず、`features.size` により列マッピングを分岐させる。想定外の列数の場合は明示的に例外を送出し、暗黙に誤った列を読まないこと。
- **ユーザー辞書併用**：`WAKA_UNIDIC_USERDIC` が設定されている場合のみ `-u` を付与する。
- **戻り値**：素性配列をそのまま外部へ露出せず、`surface / lemma / lform / pron / pos` を保持する値オブジェクト（Struct等）の配列で返す。

### ③ テストの追加

- 『水無瀬三吟百韻』等のテキストを用いた `WakaUnidicAnalyzer` の単体テスト。
- 既存 `ku_validator` のテストスイートを実行し、デグレがないことを確認。
- **辞書未配置環境ではUniDic系specをskip**し、CIが落ちない構成とすること。

### 未達項目の詳細：UniDic用ユーザー辞書のコンパイルは本フェーズでは実現できなかった

`mecab-dict-index -a`（POS名からコスト・接続IDを自動推定するモード）を試みたが、`tmp/unidic-waka/`に含まれるのは`sys.dic`・`matrix.bin`（バイナリのみ）・`char.bin`・`dicrc`・`feature.def`・`rewrite.def`・`unk.dic`・`unk.def`・`README.md`の9ファイルで、`-a`モードが要求する`left-id.def`・`right-id.def`等のコスト推定用モデルファイルが配布物に含まれておらず、`mmap_.open(modelfile.c_str())`エラーで失敗した。

明示的に左右文脈IDを数値指定する方式も検討したが、natto経由では`node.lcAttr`/`node.rcAttr`に相当する属性が取得できず（`node.methods`で確認、`wcost`のみ取得可能）、安全に既存語のIDを転用する手段がなかった。IDを推測で埋めることは誤った接続コストを生む恐れがあるため実施しなかった。

**結論：** UniDic和歌版向けのユーザー辞書運用（過剰分割対策、§4②「ユーザー辞書併用」）には、この解析用配布物とは別に、モデルファイル一式を含む構築用パッケージの入手、または他の手段（システム辞書自体への追加登録等）が必要。`WakaUnidicAnalyzer`側の`-u`オプション配線・環境変数`WAKA_UNIDIC_USERDIC`自体は実装済みだが、実際に動作するUniDic用ユーザー辞書ファイルを用意できていないため未検証のまま。次のPhase 0調査候補として切り出すことを提案する。
