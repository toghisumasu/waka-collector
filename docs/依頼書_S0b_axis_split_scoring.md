# 依頼書 S-0b：軸別呼び出しによる qwen3:8b スコアリング（S-0 の切り分け実験）

> フェーズ番号「S-0b」は仮称。既存の体系に合わせて付け替えてよい。

## 1. 目的

S-0 で、qwen3:8b の 1〜5 評価が「2/3/4」に約 75%（223/297）固着し、ペア間の差を拾えていないことが分かった。原因の候補は、3軸を1回の呼び出しで同時に出させていることによる軸間の引きずり（軸の並び順への追従を含む）。

本依頼では、**3軸を別々の呼び出しに分ける**ことだけを変え、固着が解消するかを見る（1変数原則）。判定・閾値決定・本番配線は行わない。

### 3-2. 軸別採点スクリプトの新規作成

`script/score_minase_pairs_qwen8b_split.rb`（新規・読み取り専用。S-0 のスクリプトは複製して使い、S-0 側は触らない）

**S-0 と同一に保つもの（変数にしない）**

- 実行方法：`WAKA_OLLAMA_MODEL=qwen3:8b bin/rails runner script/score_minase_pairs_qwen8b_split.rb`。未指定なら異常終了
- `/api/generate`、`stream: false`、`think: false`（API パラメータ）、`options: {temperature: 0.3, num_predict: 60}`
- `repeat_penalty` は送らない。seed は固定しない。`format: "json"` は使わない
- 各呼び出しは独立した単発リクエスト（文脈を持ち越さない）
- 前句・付句の本文のみを渡す（折・季・bui・型のヒントは渡さない）
- 尺度の文言：「1 = ほぼ同じ・非常に近い、5 = まったく異なる・非常に遠い」
- パース：最初の `{...}` を抜き出し、値が 1〜5 の整数であることを確認。失敗は1回だけ再試行、それでも失敗なら `parse_ok=false` で残す
- ペア規則：`pair_no` = 前句の句番、99ペア

**変えるもの（唯一の変数）**：1ペアにつき軸ごとに3回、別々に呼び出す。1ペア×1軸×1試行が1呼び出し。

#### プロンプト案（承認ゲートで最終化）

軸ごとに、その軸の定義1行だけを載せる。他の軸には言及しない。

season_gap:
```
あなたは連歌の付合を評価する。次の前句と付句を読み、「季節感の離れ」を1〜5の整数で評価せよ。
1 = ほぼ同じ・非常に近い、5 = まったく異なる・非常に遠い。

JSONのみを出力せよ。説明は不要。
{"season_gap": n}

前句：{maeku}
付句：{tsukeku}
```

material_gap（軸の定義行だけを「句材（題材）の離れ」に替える）、scene_gap（同じく「情景の離れ」に替える）も同じ構成。キー名はそれぞれ `material_gap`、`scene_gap`。

- 置換は `gsub` で行う（`format` は使わない）
- 呼び出し順は、試行 → ペア → 軸の順。各呼び出しは独立なので、順序は結果に影響しない想定

#### 出力（S-0 と別ファイル）

1. `tmp/minase_qwen8b_split_raw.csv`（呼び出し単位）
   - 列：`pair_no, maeku, tsukeku, axis, trial, gap, parse_ok, retried, raw_output`
   - ヘッダーのコメント行は **CSV のクォートを通さず生テキストで書く**（S-0 で直した点）。読むときは `CSV.read(path, headers: true, skip_lines: /\A#/)` が必要である旨もヘッダーに書く
   - コメント行に、モデル名・応答の model フィールド・temperature・num_predict・think・repeat_penalty 未送信・seed 未固定・実行コマンド・実行日時・プロンプト全文3本を記録
2. `tmp/minase_qwen8b_split_summary.csv`（ペア単位・99行）
   - 各軸の中央値・最小・最大（3試行）
   - `bui_distance`（`tmp/minase_bui_distance_report.csv` から `pair_no` で結合）
   - `unstable`（いずれかの軸で最大と最小の差が2以上）
   - S-0 の中央値を並べた列（`s0_season, s0_material, s0_scene`）

### 3-3. 実走前の確認（3ペア）

pair_no = 1、71、および S-0 で `season_gap` が 5 だったペアから1つ、の計3ペアを 3軸×3試行（27呼び出し）で走らせ、parse 成功率と出力の形（`n` のオウム返し、`<think>` の混入など）を確認する。問題があれば **全走せずに報告して停止**。問題が無ければそのまま全走へ進む。

### 3-4. 全走と記述統計（判断はしない）

全走は 99 × 3軸 × 3試行 = 891 呼び出し。1呼び出し約 0.5〜1 秒として 8〜15 分程度。`nohup` で実行し、ログを `tmp/` に残す。途中再開機能は持たせない。中断時は既存出力を枝番付きで退避して最初からやり直す。

標準出力に以下を出し、報告に貼る。**解釈・閾値の提案はしない。**

1. 各軸の値の度数分布（1〜5）と、最頻値の占有率。S-0 の値と並べる
   - S-0：season 2 が 228/297、material 3 が 226/297、scene 4 が 226/297
2. 3軸の組の種類数と、最頻の組の占有率（ペア×試行の組。S-0 は 10 種類、「2/3/4」が 223/297）
3. `unstable` の件数と一覧（S-0 は 5 件：17, 51, 88, 91, 94）
4. 各軸中央値と `bui_distance` の Spearman 相関（同順位は平均順位）。S-0 の参考値：season 0.257 / material 0.279 / scene 0.292。同順位の多さも併記
5. pair_no = 1 と 71 の3軸の値（S-0 では両方「2/3/4」）
6. **季移りの照合（LLM 呼び出し不要）**：原表の季欄で季移りの有無を定義（春・夏・秋・冬・無季の区分が前句と付句で違えば「あり」。雑↔恋は季移りにしない）し、99ペアを層別して、S-0 と S-0b それぞれの `season_gap` 中央値の平均と度数分布を「あり」「なし」別に出す
7. parse 失敗率、再試行数

## 9. 結果の読み方の目安（判断は Nobuson）

- 「2/3/4」の占有率と各軸の最頻値の占有率が大きく下がり、季移りありのペアで `season_gap` が上がっていれば、分割で改善したと読める
