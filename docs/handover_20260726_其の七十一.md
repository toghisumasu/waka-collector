## 2. must_switch: true ブランチの発火確認

`log_season_hint`（`SeasonHintLogger`、D-52-1）は`Rails.logger.info`経由で`log/development.log`に出力されるため、jsonlログではなくdevelopment.logを参照した。development.logには過去の走行分も蓄積されているため、`verse_no`が100→1に戻る境界（1回のみ検出、development.log 5405〜10046行目）で今回の走行分（63行）を切り出した上で確認した。

**結果：must_switch: trueが5回発火した。**

```
[SeasonHint] verse_no=54 season=秋 count=5 must_switch=true must_continue=false
[SeasonHint] verse_no=64 season=秋 count=5 must_switch=true must_continue=false
[SeasonHint] verse_no=71 season=秋 count=5 must_switch=true must_continue=false
[SeasonHint] verse_no=89 season=春 count=5 must_switch=true must_continue=false
[SeasonHint] verse_no=94 season=秋 count=5 must_switch=true must_continue=false
```

sono51_run1で未検証だったギャップは解消した（ただしsono51_run1はD-52-1実装＝其の五十二より前の走行のため、そもそもSeasonHintLoggerのログ自体が存在しない点に注意。「未検証」というより「計装が存在しなかった」が正確）。5回とも`count=5`（連続5句到達）で発火しており、`kukazo_rules.yml`の`bui.恋.max`等と同型の上限到達トリガーが設計通り機能していることが確認できた。
